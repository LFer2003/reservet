# Архитектурные соглашения

[Español](../ARQUITECTURA.md) · [English](../en/ARCHITECTURE.md) · **Русский**

Reservet начинается как модульный монолит: один HTTP-процесс и PostgreSQL.
Воркер появится в задании с очередями. Добавляйте сервисы только при наличии
потребности, которую можете объяснить и проверить.

## Ответственность частей системы

| Часть                              | Ответственность                                           |
| ---------------------------------- | --------------------------------------------------------- |
| `src/server.ts`                    | Запуск HTTP и освобождение ресурсов по сигналам           |
| `src/app.ts`                       | Middleware, маршруты и ошибки HTTP                        |
| `src/shared/config.ts`             | Загрузка и проверка конфигурации при запуске              |
| `src/shared/database.ts`           | Пул и ограничения подключений и запросов                  |
| `src/modules/<module>/*.routes.ts` | Проверка входных HTTP-данных и преобразование результатов |
| `*.service.ts`                     | Бизнес-правила и координация транзакций                   |
| `*.repository.ts`                  | Параметризованный SQL и преобразование строк БД           |
| `public/`                          | Представление и работа с HTTP                             |
| `migrations/`                      | Версионируемые изменения схемы                            |

Зависимости идут от маршрутов к сервисам и репозиториям. Три файла — ориентир для
первого задания, а не повод создавать пустые слои. Сервис не должен зависеть от
Request/Response Express.

## Данные и ошибки

- Проверяйте входящий JSON на сервере: TypeScript не валидирует внешние данные.
- Используйте ограничения PostgreSQL вместе с проверками приложения.
- Используйте параметры SQL; не объединяйте запрос с пользовательскими строками.
- Ожидаемые ошибки преобразуйте в 400, 404 или 409, а не в 500.
- Для новых бизнес-ошибок возвращайте `{ code, message, requestId }`, например
  `TABLE_NAME_CONFLICT`. Интерфейс сможет переводить `code` независимо от языка
  `message`. Эндпоинты столиков остаются заданием начинающего разработчика.
- Не раскрывайте стеки вызовов, запросы, пароли и полные объекты Error.
- Не записывайте в логи тела запросов, пароли и ненужные персональные данные.

Транзакция должна использовать одно подключение от BEGIN до COMMIT/ROLLBACK,
освобождаемое в `finally`. Не выполняйте её шаги через `pool.query`: они могут
попасть на разные подключения. Проверяйте конкурентные запросы при работе с бронированиями.

Миграции запускаются явно: транзакция на файл и блокировка между исполнителями.
При старте HTTP они не выполняются. Учебный исполнитель не поддерживает
автоматический откат и контрольные суммы: неизменность применённых миграций
обеспечивается соглашением и проверкой кода.

## Интерфейс и языки

`public/app.js` управляет одним экраном; `public/i18n.js` содержит переводы и
настройку языка. При добавлении экранов разделяйте модули по функциональности.
Значения контракта HTTP, например `available`, одинаковы во всех языках.

Внешние данные вставляются через `textContent`; HTML-шаблоны содержат только
константы. Режим демонстрации явно обозначен и не скрывает ошибки API.
У запросов есть тайм-аут; повторная отправка блокируется на время ожидания.
Для шрифтов есть локальные альтернативы, запросы к сторонним ресурсам не нужны.

## Границы и проверка

По умолчанию сервер слушает localhost. В Docker он слушает интерфейсы контейнера,
но порт публикуется только на localhost хоста. См. [окружения и пайплайн](DEPLOYMENT.md).
Учётные данные примера — локальные.
Helmet задаёт заголовки и CSP; локальный HTTP не принуждает к HTTPS/HSTS.
При развёртывании проверьте HTTPS, источники запросов, секреты и права доступа.
См. [официальные рекомендации Express](https://expressjs.com/advanced/best-practice-security/).

Аутентификация и авторизация — задания начинающего разработчика; это локальная
учебная среда. SQS, outbox, роли, ограничение частоты запросов и полноценная
наблюдаемость появятся в соответствующих заданиях. Текущие тесты не проверяют
миграции на реальном PostgreSQL и не заменяют визуальную проверку в браузере.

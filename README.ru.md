# Reservet · Управление столиками

[Español](README.md) · [English](README.en.md) · **Русский**

Приложение для сотрудников ресторана: вход в систему, управление столиками и
хранение данных в PostgreSQL. Решение технического задания Reservet для junior-разработчика.

[Репозиторий](https://github.com/LFer2003/reservet) ·
[Проверки GitHub](https://github.com/LFer2003/reservet/actions/workflows/ci.yml) ·
[Решения и исправления, на испанском](docs/ENTREGA.md) · [Исходное задание, на испанском](docs/ENUNCIADO.md)

## Возможности

- Вход, проверка текущей сессии и выход с отзывом сессии на сервере.
- Пароли с scrypt, сессии PostgreSQL со сроком действия восемь часов.
- Создание и просмотр столиков; статусы «свободен», «занят», «не обслуживается».
- Поиск без учёта регистра, фильтры через сводку и сброс фильтров.
- Компактные карточки: название, вместимость, статус и его изменение.
- Сводка свободных столиков и мест, адаптивный интерфейс на трёх языках.
- Режим API с сохранением данных и демонстрация с временными данными в памяти.

## Локальный запуск

Нужны Git, Node.js 22.13 или совместимая более новая версия, npm и PostgreSQL 17.
Docker и развёртывание не требуются.

```powershell
git clone https://github.com/LFer2003/reservet.git
cd reservet
npm ci
# Только если .env ещё нет:
Copy-Item .env.example .env
```

От имени администратора PostgreSQL выполните команды по отдельности с autocommit:

```sql
CREATE ROLE reservet_candidate LOGIN PASSWORD 'local_candidate_password';
CREATE DATABASE reservet_candidate OWNER reservet_candidate;
CREATE DATABASE reservet_candidate_test OWNER reservet_candidate;
```

Это примеры локальных учётных данных. При совпадении имён выберите другие.
Пользователю приложения не нужны права суперпользователя. Настройте `.env`:

```dotenv
PORT=3000
HOST=127.0.0.1
APP_ENV=dev
DATABASE_URL=postgresql://reservet_candidate:local_candidate_password@localhost:5432/reservet_candidate
TEST_DATABASE_URL=postgresql://reservet_candidate:local_candidate_password@localhost:5432/reservet_candidate_test
```

Укажите свои порт и учётные данные; специальные символы пароля кодируйте для URL.
Не публикуйте `.env`. Тестовая база должна отличаться от основной, а её имя —
заканчиваться на `_test`.

```powershell
npm run db:migrate
$env:SEED_USERNAME = 'demo'
$env:SEED_PASSWORD = Read-Host 'Локальный пароль длиной не менее 12 символов'
npm run db:seed-user
Remove-Item Env:SEED_PASSWORD
npm run dev
```

Повторный seed обновляет пароль указанного пользователя. Публичной регистрации и
общего пароля в репозитории нет.

Откройте [http://localhost:3000](http://localhost:3000), войдите и выберите **Мой
локальный API** для проверки сохранения. В демонстрации изменения исчезают при
перезагрузке. `/health` должен вернуть `status: ok`, `/health/db` — `database: connected`.
Для запуска скомпилированного кода: `npm run build`, затем `npm start`.

## Проверки

```powershell
npm run check
npm run test:integration
```

`check` запускает lint, форматирование, проверку типов, тесты конфигурации/HTTP/UI и
сборку. `npm test` использует JSDOM и имитацию fetch/запросов проверки базы, без
настоящей PostgreSQL. Интеграционные тесты требуют `TEST_DATABASE_URL`: создают
изолированную случайную схему, применяют миграции и удаляют только эту схему.
Проверяются вход, защита маршрутов, операции со столиками, валидация, конфликты,
отсутствующие столики, выход, истечение сессии и сохранение после перезапуска
HTTP-сервера, полного перезапуска процесса Node и через другое соединение с БД. Миграции и seed запускаются дважды для проверки повторяемости. Нужны права на создание схем;
предварительная миграция тестовой базы не требуется.
GitHub Actions поднимает PostgreSQL 17 и запускает обе группы тестов и прежние проверки.

## Архитектура, безопасность и решения

Маршруты HTTP, сервисы и SQL-репозитории разделены в `src/modules/auth/` и
`src/modules/tables/`. Интерфейс находится в `public/`.
Токен сессии случаен; PostgreSQL хранит его хеш. Cookie имеет `HttpOnly`,
`SameSite=Lax` и срок восемь часов. `Secure` включается при `APP_ENV=pro`;
локально используется HTTP в пределах одного origin. Выход удаляет сессию и cookie.
Все маршруты столиков защищены. Есть серверная валидация, параметризованный SQL,
ограничения БД и вставка внешних текстов через `textContent`.

Компактные карточки выбраны для удобства работы вместо декоративных рисунков столиков.
Codex помогал с проверкой кода, исправлениями, дизайном, тестами и документацией.
Исправленное решение: при ошибке выхода интерфейс раньше скрывался, теперь он
показывает ошибку и позволяет повторить попытку. Это покрыто регрессионным тестом.
Подробный журнал причин, исправлений и тестов доступен в испанской документации.

## Объём решения

Приложение реализует аутентификацию и управление столиками. Бронирования, платежи,
склад, сложные роли, восстановление пароля и развёртывание не входят в задание.
Просроченные сессии отклоняются, но их строки не очищаются по расписанию.
[Отчёт о проверке, на испанском](docs/VERIFICACION.md) содержит результаты
сопоставления с требованиями и подтверждённые проверки.

# Работа над Reservet

[Español](CONTRIBUTING.md) · [English](CONTRIBUTING.en.md) · **Русский**

Для технического задания [главный README](README.ru.md) определяет задачи и сдачу
в вашем репозитории. Docker и развёртывание не нужны; не отправляйте PR в исходный
репозиторий. Эти соглашения — вспомогательный материал.

Начните с [руководства](docs/ru/JUNIOR_GUIDE.md) и
[архитектурных соглашений](docs/ru/ARCHITECTURE.md).

## Рабочий процесс

1. Определите ожидаемое поведение и ошибочные сценарии.
2. Создайте ветку для задания, например `feat/list-tables`.
3. Запустите `npm ci` и `npm run check`, чтобы проверить исходное состояние.
4. Реализуйте небольшое изменение, которое сможете объяснить.
5. Добавьте тесты поведения и существенных ошибок.
6. Просмотрите `git diff`, запустите `npm run check` и опишите проверку результата.

## Соглашения

- Имена в коде и названия файлов — на английском; учебная документация доступна
  на испанском, английском и русском.
- Используйте UTF-8, LF и отступ в два пробела согласно `.editorconfig`.
  Избегайте инструментов, преобразующих многоязычный текст в другую кодировку.
- В бэкенде включён строгий TypeScript. Избегайте `any` и приведений типов,
  скрывающих непроверенные данные.
- Предпочитайте `const`, понятные имена и функции с одной ответственностью.
- Комментируйте причины неочевидных решений, а не каждую инструкцию.
- Добавляйте зависимости и слои, только если можете объяснить их необходимость.
- Не добавляйте в репозиторий `.env`, пароли, реальные данные клиентов и содержимое логов.
- Создавайте новые миграции; не изменяйте уже применённые.
- Проверяйте три языка интерфейса. Не переводите пользовательские названия.
- При изменении инструкций обновляйте все три языковые версии документации.

## Команды проверки качества

```powershell
npm run format       # Единое форматирование
npm run lint         # Поиск проблем в коде
npm run typecheck    # Проверка типов бэкенда и скриптов
npm test             # Тесты конфигурации, HTTP и интерфейса
npm run build        # Сборка бэкенда
npm run check        # Все проверки, включая форматирование
```

Тесты используют Node и JSDOM без подключений к реальным PostgreSQL, AWS и внешним
провайдерам. JSDOM не проверяет внешний вид: отдельно проверяйте браузер, мобильную
версию и управление с клавиатуры. Для репозиториев добавляйте интеграционные тесты
с отдельной тестовой базой, никогда с рабочими или производственными данными.

После размещения проекта на GitHub Actions запускает `npm run check`.
Описывайте проблему, полученный результат и подтверждение проверки.
Не отключайте проверки ради успешной сдачи.

## Совместимость

TypeScript 5.9 и ESLint 9 совместимы с Node 22.13 и typescript-eslint.
Перед обновлением основных версий проверяйте диапазоны совместимости и запускайте
все проверки. Не скрывайте конфликты зависимостей флагами `--force` или `--legacy-peer-deps`.
